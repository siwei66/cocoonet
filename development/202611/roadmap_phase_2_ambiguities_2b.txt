Execution meta data and filesystem layout are two things, file system layout should not be redundant for the convenience of the users, there are two meta data layers unnecessary: parent layer and attempt layer, because the root work dir is specified for one computation instance / parent task, so the dir has only one parent for the root node.
Besides, one attempt evaluates only one model and one model is only evaluated by one attempt. A model can be fitted independently in folds of an attempt, but they are the same model assigned. The attempt layer is unnecessary for both root and worker. On the worker side, one model only has one attempt. On the root side, if it received the result of one model, it asks stop of all other attempts of that model and drops the result coming later of the attempts of that model even if it's finished and sent. So root side one model only has one attempt too. As a result, there is no need to make them two layers for file persistence. I prefer both worker and root use model layer only.

  execution_state.csv
