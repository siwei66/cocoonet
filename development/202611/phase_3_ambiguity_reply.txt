5. How should singular and bulk mutations share validation logic?
Separate the validation with the adding operation itself, `add_model()` call internal helper validator first and call the operator, and call them once. Bulk `add_models()` simply call validator for every member and then call operator for every member, so that one failure will reject the operation / adding of the entire bulk.

The shallow copy behavior should be simply a double reference, and a explicit warning should be printed out loudly when shallow copy is applied.

Define the deep copying behavior as follows:
- Copying automatically create a new work dir for the copied instance, the work dir is in the same parent dir with the original work dir and the name of the new work dir is `<the original name>_copy_<6-digit random code using numbers and lower case letters>`
- Copy all existing subdirs with all files to the new work dir
- The new instance configure the new work dir with copied files as its work dir, so no conflict exists, any following operation on the copied instance will be operated using the new work dir.
