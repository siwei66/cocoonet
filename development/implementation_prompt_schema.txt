## Phase initial prompt schema:

```text
Read `AGENTS.md` and `roadmap_phase_1.md`, and the corresponding part of `architecture.md`, continue with the first unit of phase 1.
```

## Phase continuing prompt schema:

```text
Approved. Implement the proposed changes directly. Do not introduce other change beyond the proposal.

---

After finishing：
- Verify the compliance of current implementation to the development requirement of `AGENTS.md`, delivery a compliance report.
- Verify the over-engineering risk specifically i.e. verify the risk of too many layer of nesting, over-complicated logic, over-defensive for a light-weight python module and functional or coding redundancy in the context of `roadmap.md` and the phase roadmap. Considering whether a demand is really needed in the real implementation of current step and current phase, instead of view all roadmap demands as ground truth to follow. Deliver a over-engineering risk report.
- Then, propose a standard one-line git commit message for the changes with scope. If the changes have multiple associated scopes, propose one git commit message for each associated scope.
- At last, show me the progress of implementation of the current phase, list the implemented units and the units to be implemented in the current phase.

---

Then, if there is no violation or major over-engineering risk or risk of unnecessary required functionalities, continue with the next unit.

Propose only. The proposal requirements are same:

- Prepare only the next planned change unit.
- Show me the exact proposed implementation and corresponding tests, with a concise explanation of the change and any relevant implementation decision.
- Deliver the proposal in python code block with filename and the number of the line in the file to add the block.
- Read only the relevant `AGENTS.md` rules, the relevant `architecture.md` design, and the applicable section of the detailed phase roadmap of the current phase, and the directly affected code/tests.
- Do not perform a broad repository audit unless required by a detected dependency.
- Propose the exact change only.
- Do not modify files for next unit.
```

====================================================================
